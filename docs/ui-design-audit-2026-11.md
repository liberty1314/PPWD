# PPWD 整体 UI 与排版审计

审计日期：2026-11-10
覆盖范围：`ppwd-desktop` 桌面端、`ppwd-extension` 扩展弹窗。当前仓库不包含官网、Web 端或服务端 UI，因此不对这些已移除模块做视觉结论。

## 结论摘要

整体界面已经形成一致的浅色工作台框架，侧栏、页面标题、表单、设置导航和保险库双栏结构清楚，中文层级也容易辨认。当前最值得投入的不是推倒重做，而是提高工作区有效信息密度、让高频流程更直接、统一控件边界语言，并补齐扩展弹窗的有限空间策略。

优先级最高的调整：

1. **P1：重新平衡桌面端宽屏内容宽度。** 1700px 截图里，主内容被限制在约 940px 的居中区域，左右留下大量空白；密码库详情又只占主区的一部分。可把工作区改为弹性宽度，并按页面设置上限：仪表盘适度放宽，保险库列表/详情按比例分配，设置表单保持可读行宽。
2. **P1：明确设置页分区与滚动关系。** 设置子导航在页面顶部，选项纵向铺开；长页面需要滚动较久，切换分区后缺少位置提示。考虑让分区导航在滚动时保持可见，并为安全、备份等长页面加清楚的小节标题和锚点。
3. **P1：改善保险库列表与详情的操作优先级。** 当前每行同时呈现主选中、收藏和“更多”，详情再放返回、收藏、编辑、更多，主操作分散。建议把编辑作为明显主动作，低频动作统一收进菜单；列表行增加最近修改/类型等有区分度的信息，避免只靠标题和用户名扫描。
4. **P2：统一表面和边框的视觉语汇。** 首页和设置多使用细分隔线，密码库筛选区和详情却出现较重的矩形边界，部分操作按钮也有较强描边。统一边框对比度、圆角层级与控件高度，突出当前焦点，而不是让每个区域都像独立面板。
5. **P2：安全中心让统计可解释且可操作。** 指标卡直接给出弱密码、重复密码数量，但列表将每条问题分别展开；示例中 3 项登录记录显示 3 个弱密码和 3 个重复密码，容易让用户不清楚它们是否重叠。建议在数字下方说明问题口径，支持按风险类型筛选，并在列表显示风险级别和下一步动作。
6. **P2：收紧扩展离线态的垂直留白。** 420×640 截图中品牌、状态区、主按钮和重新检测分散在弹窗上下，核心动作区的聚合感较弱。将连接状态与说明放在同一紧凑区域，按钮靠近状态信息；官网链接保留底部，但可减小其与主体间距。

## 全局设计系统

### 做得较好的地方

- 桌面端固定侧栏让首页、密码库、收藏、最近访问、安全中心和设置的去向明确。
- 主要按钮、开关、输入框和标签均有清楚的文本语义；安全相关按钮使用图标辅助但不依赖图标猜义。
- 密码库采用列表与详情并列的工作台形态，适合频繁查找和复制；密码默认遮蔽并提供独立显隐控制。
- 设置采用顶部分类切换，主题外观页通过模式、设计风格和强调色分层组织。
- 扩展离线连接状态清楚说明前置条件，并提供唤起桌面端和重新检测入口。

### 可系统化调整

- **宽度规则：** 按页面类型定义内容宽度，不使用单一窄列规则套全部页面。密码库应优先给列表和详情可用宽度；仪表盘卡片和两列区域可随窗口增长；设置页则让描述与控件保持稳定的阅读距离。
- **间距规则：** 页面标题到首个内容区、筛选区到结果列表、分区标题到首行采用固定间距档位，避免各页之间疏密不一。
- **边框规则：** 主工作区不必同时依赖整框描边、行分割线和按钮描边。用浅色分隔线建立结构，只有选中、输入焦点、危险区域或真正独立的表单面板才使用明显边界。
- **状态规则：** 空、加载、断开、权限不足、无匹配等状态使用一致的图标尺寸、文案宽度和操作位置。扩展与桌面端尤其需要同一套“状态说明 + 单一下一步动作”布局。
- **色彩规则：** 当前浅色界面以低对比灰白为主，蓝色强调较克制；建议检查灰色文字在低亮度显示器上的对比度，并确保选中、成功、警告和危险色不只靠色相表达。

## 逐屏截图与观察

下列截图来自 ego lite 浏览器中的实际渲染。桌面页面通过本地模拟 preload/本地保险库返回值进入目标状态；凭据为合成样例，不含真实用户数据。扩展的离线态和设置页通过浏览器里的 Chrome API 测试替身运行。

### 1. 首次创建保险库

![首次创建保险库](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/setup.png)

- **观察：** 左侧品牌区与右侧主任务分栏明确；表单居中，按钮层次清楚。重置本机数据按钮紧邻继续按钮，且使用醒目的红色边框/文字，容易和正常流程产生不必要的竞争。
- **调整：** 将重置操作放到低显著性的独立辅助区，或放进页脚二级操作；首次创建说明可拆成“仅本机保存”“不会导入旧数据”两条简短信息，减少长句阅读负担。
- **证据限制：** 当前截图是宽屏首屏。建议另测 1024×700 和较小窗口，确认左侧说明不会挤压右侧表单。

### 2. 桌面首页

![桌面首页](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/dashboard.png)

- **观察：** 三个统计入口、最近访问、安全提示和快捷操作均可见；信息组之间有分隔，初次使用时也能看到空状态。页面实际内容占宽有限，宽屏两侧留白明显；安全提示区和快速操作区在视觉上容易被读成普通文本块。
- **调整：** 放宽主内容列，或让“最近访问”成为左侧主列、“安全与快捷操作”作为较窄侧列；安全提示保留一个明确的风险摘要或下一步动作，减少泛化安全建议。
- **证据：** 本图为无条目的模拟保险库状态，主要用于检查空态和布局。

### 3. 密码库：空库

![密码库空态](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/vault-empty.png)

- **观察：** 搜索、类型、排序和批量选择都在结果区上方，结构完整；空库下仍然保留左右双栏，右侧显示“选择一个项目查看详情”，和“暂无密码条目”并列后会让空状态显得像操作失败或尚未选择。
- **调整：** 条目数为零时合并双栏空状态，在空状态中突出“新增项目”和“导入密码”；有数据时才显示详情面板。筛选控件可按宽度自动折行，避免小窗口横向拥挤。

### 4. 密码库：有条目与详情

![密码库有条目](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/vault-populated.png)

- **观察：** 列表和详情关系清楚，字段名、字段值和复制按钮可辨；但详情区内容最大宽度偏窄，左右留白较大。列表行只展示名称和一条副信息，不同类型条目的副信息语义不完全一致；顶部筛选栏的多个描边控件形成较重的横向边框带。
- **调整：** 让列表栏维持稳定最小宽度、详情栏弹性扩展；详情标题操作集中为收藏、编辑和更多。结果行可显示类型或最近修改时间，并保证副信息长文本截断时仍能区分网站、用户名和主机。
- **响应式：** 1100px 窗口测试下双栏仍可用，但筛选项已接近拥挤。窄窗口时应将筛选器折行或移入筛选菜单，并考虑选中详情改为独立页/抽屉。

### 5. 安全中心

![安全中心](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/security-center.png)

- **观察：** 三个指标在顶部一眼可见，风险条目可直接打开；但指标与条目没有分组或筛选关系，数字含义不够自解释。页面中部以下空白较多。
- **调整：** 为每个指标补充口径或可点击筛选；按弱密码、重复密码、长期未更新分组，条目显示风险原因、最近更新日期和建议动作。无问题时用同一位置展示明确的健康状态。

### 6. 设置：通用

![设置通用](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/settings-general.png)

- **观察：** 分类清楚、描述靠近对应控件，开关和下拉对齐良好；语言项重复出现通用说明“管理安全、外观与系统偏好”，对当前设置的解释价值较低。多行设置全部用横线串接，页面会显得像很长的连续清单。
- **调整：** 为语言、数据目录等行提供各自准确的辅助说明；将“启动与窗口”“语言与字体”“本地存储”等拆成有标题的组。分组标题应帮助扫描，不增加额外卡片边框。

### 7. 设置：外观

![设置外观](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/settings-appearance.png)

- **观察：** 模式、主题设计和强调色从整体到局部的顺序合理；强调色只显示色点，当前所选状态依赖边框或辅助状态，快速辨认度一般。
- **调整：** 色点显示清晰的选中勾或单选状态，并保证键盘聚焦可见；主题设计可以用小型真实预览展示材质与层级变化，帮助用户理解“液态玻璃”等模式的区别。

### 8. 设置：安全

![设置安全](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/settings-security.png)

- **观察：** 自动锁定、剪贴板清除、生物识别、令牌绑定和换绑表单放在同一长页；换绑说明和输入表单清楚，但与上方偏好项的视觉分组相近，敏感操作的风险级别没有明显抬高。
- **调整：** 将“保险库保护”和“手机令牌”做成明确小节；换绑区在视觉上与普通偏好分开，并把主密码、动态码字段和验证按钮组成紧凑流程。危险/敏感操作的状态色和确认方式保持统一。

### 9. 设置：快捷键

![设置快捷键](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/settings-shortcuts.png)

- **观察：** 快捷键与功能描述一一对应，按键录制控件显眼；页面只有两项但仍沿用完整设置长页结构。
- **调整：** 两条快捷键可压缩成紧凑的“动作 / 说明 / 按键”行；录制态增加明确取消或恢复操作的提示，并保留冲突反馈在同一行附近。

### 10. 设置：加密备份

![设置备份](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/settings-backup.png)

- **观察：** 导出密码、导入替换和危险操作都在一屏出现；备份说明与密码输入靠近。清空保险库和重置本机数据名称接近、影响范围较大，视觉上却和其它设置项同级。
- **调整：** 把危险操作收进独立危险区，明确区分“清空保险库”和“重置全部本机数据”的影响范围；把备份导入前需要先导出当前备份的说明放在导入按钮旁。

### 11. 扩展弹窗：桌面端未连接

![扩展离线状态](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/extension-popup-offline.png)

- **观察：** 前置依赖和连接状态表达清楚，主动作“打开桌面端”突出；状态卡、按钮和重新检测在垂直方向分散，主体上方留白较多。
- **调整：** 缩短品牌区与状态卡间距，把重新检测作为次级按钮放到状态说明旁；按浏览器弹窗常见高度优化内容重心，减少用户需要扫视的距离。
- **说明：** 页面由浏览器 API 测试替身渲染，连接状态来自模拟的未连接返回值。

### 12. 扩展设置

![扩展设置](/Users/abner/Desktop/MyProject/PPWD/docs/ui-audit-2026-11/extension-settings.png)

- **观察：** 桌面连接说明与版本/作者/官网信息分区明确；底部重新检测按钮位置稳定。桌面端状态和“主题语言跟随桌面端”的说明有部分语义重复。
- **调整：** 状态区用一条简短说明说明当前可用性；重新检测成功后在同一处展示结果。作者和官网属于低频信息，可以弱化视觉权重，保持连接状态和下一步动作优先。

## 建议实施顺序

1. **先做布局校准：** 在 1280、1440、1700px 三档桌面宽度和 1100px 最小窗口下，调整页面内容宽度、双栏比例、筛选栏换行及空库布局。
2. **再统一高频操作：** 整理密码库行操作和详情动作，统一按钮高度、边框、焦点、选中态与风险状态。
3. **优化长页扫描：** 给通用、安全、备份设置加入清晰分组和危险区；使分区导航保持容易到达。
4. **最后收紧扩展弹窗：** 以 360×560 和 420×640 两档检查连接、空匹配、有匹配、设置和错误状态。

## 证据与限制

- 桌面端通过本地 Vite/Electron renderer 和浏览器 preload 测试替身截图；数据为合成样例，未连接真实保险库。
- `vault-narrow.png` 是 1100px 窗口宽度检查，其他桌面截图约为 1700×860。截图中浏览器测试环境右侧的粉色翻译悬浮按钮属于测试浏览器扩展叠层，不是 PPWD 产品界面。
- 扩展离线页与设置页在 420×640 测试视口下渲染；解锁后的扩展凭据列表未取得可靠截图，因此本报告不对该状态的视觉细节作强结论。
- 本次审计只分析 UI 和布局，不包含可访问性自动化、真实数据密度、Windows/macOS 原生窗口差异或键盘完整流程测试。
