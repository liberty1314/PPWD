# BearPassword 二次开发需求文档（本地版）v3 定稿

- **基线项目**：https://github.com/isxuewei/BearPassword.git（桌面端版本 26.9.9；Electron + Vue 3 + TypeScript）
- **文档版本**：v3 定稿 · 2026-11-04（在 v2 基础上按用户 7 条确认修订；此前待确认项已全部关闭，本版可直接作为开发依据）
- **一句话目标**：只在本地运行的单机桌面密码管理器——无服务器、无网页端、无官网站、无账号，打开软件用主密码 + 手机验证器令牌验证。

## 1. 产品形态定稿

- **唯一交付物**：`bear-password-desktop` 桌面端（macOS、Windows），外加保留的 `bear-password-extension` 浏览器扩展（本机桥接，见第 7 节）。
- **删除物**：
  - `bear-password-server/`（Java + Spring Boot + MySQL + Redis）
  - `bear-password-web/`（网页端）
  - `bear-password-index/`（官网静态页：`index.html`、静态资源与构建脚本）
  - 根构建脚本中的 web / server / index 步骤，根 `package.json` 中对应的构建脚本。
- **运行条件**：Node.js 18+、npm 9+（仅开发与打包用）；**用户使用时不再需要 Java、Maven、MySQL、Redis、Nginx、网络**。
- **正常使用零网络请求**：断网是常态而非降级模式；任何需要联网的功能在 v3 中都不存在。

## 2. 本地保险库定稿

- 以原项目已有的离线保险库为唯一数据层：`shared/offlineVault.ts` + `electron/main/offlineVaultStorage.ts` + `electron/main/offlineVaultIpc.ts`，本地文件 `vault-data.json`（条目、收藏、最近访问）。
- 删除“离线模式开关”这个概念：不再有在线 / 离线两种模式，不再有模式切换、服务端拉取后合并的分支。`src/api/vault.ts / favorites.ts / recent.ts / dashboard.ts / vaultRaw.ts` 中原来 `shouldUseOfflineVault()` 的服务端分支全部删除，只留本地分支；`src/utils/offlineVaultMode.ts` 的开关逻辑随之废弃。
- 加密不动算法：主密码 PBKDF2 + 账户密钥 HKDF 派生 32 字节 VUK，条目 AES-GCM-256；敏感材料走 Electron `safeStorage`。v3 不引入新加密算法、不改动已加密条目的解密路径。
- 保留的条目与体验：登录（含 URL、邮箱、地址、电话、备用密码、条目内 TOTP）、安全备注、身份、银行卡、服务器、数据库、两步验证、自定义；收藏、最近访问（上限 200 条）、搜索、标签、自动锁定、剪贴板清空、强密码生成、主题与中 / 英 / 日界面。

## 3. 手机令牌验证定稿（通用验证器 TOTP）

### 3.1 原则

1. 令牌是“开门验证”，不是解密密钥的替代品：真正解密仍靠本地密钥材料；令牌只证明持手机的人在场。
2. 验证全程本机完成：桌面端用已有的 `otpauth` 依赖（`src/utils/totp.ts` 已在用）在本地校验动态码，不发任何请求。
3. 三套密钥互不混用、互不可见：**开锁令牌密钥**（本节）与**条目内各网站 TOTP 密钥**与**恢复密钥**（第 4 节）是三套独立材料，不得共用存储键、不得在同一界面混显。

### 3.2 首次绑定

1. 创建本地保险库（设主密码、生成恢复密钥，见第 4 节）后进入绑定页。
2. 桌面端生成随机令牌密钥（≥ 160 bit），生成 `otpauth://` 二维码 + 手动密钥明文（仅展示一次）。
3. 用户用手机验证器 App 扫码添加，桌面端要求输入当前 **6 位**动态码验证绑定成功后才算完成；验证失败不保存密钥。
4. 未完成绑定不得进入主界面；绑定页可回退到“重新生成密钥”，旧密钥作废。

### 3.3 日常解锁

1. 打开软件 → 解锁页（不再有登录 / 注册页）。
2. 输入主密码 → 输入手机验证器当前动态码 → 本机校验通过 → 派生 VUK → 解锁。
3. 错误提示统一为“验证失败”，不区分主密码错还是令牌错。
4. 校验规则：30 秒周期；允许 ±1 个时间步长容差（手机与电脑时钟偏差）；同一动态码在同一周期内只能成功使用一次（防重放）；连续失败 5 次锁定 1 分钟，10 次锁定 15 分钟并记本地审计日志（仅事件与时间，不记密钥与动态码）。

### 3.4 换绑、解绑与丢失恢复

- 换绑：设置中操作，需同时通过“旧令牌 + 主密码”验证；通过后旧密钥立即作废，新密钥按 3.2 流程绑定。
- 解绑：不提供“一键关闭令牌验证”入口——关闭即回到单因素，等同降级，v3 不做。
- 手机丢失：凭“主密码 + 恢复密钥”进入恢复流程，重新绑定新手机；仅靠“忘记令牌”按钮、仅靠主密码、仅靠恢复密钥中的任一单项都不能直接进入保险库。
- 恢复密钥的常驻查看入口必须再次通过手机令牌验证（见第 4 节）。

### 3.5 令牌密钥存储

- 只存加密形态，走 Electron `safeStorage`（与现有 `electron/main/securityKeyStorage.ts`、`vaultPasswordStorage.ts` 同一机制），绝不以明文写入 `vault-data.json`、日志、配置文件。
- 二维码展示后立即从界面清除；不缓存二维码图片，不写入剪贴板历史之外的持久化位置。

## 4. 恢复密钥定稿（沿用原账户密钥格式）

本节回答 v2 待确认项“恢复密钥格式”，结论是不改格式、只改名称与展示上下文。

- **长度与字符集**：沿用原账户密钥——**128 位字符**，由 96 字节密码学随机数经 Base64URL 编码得到（`+` / `/` 分别替换为 `-` / `_`），生成逻辑复用原 `generateAccountSecretKey`（`src/utils/vaultCrypto/vaultKeyDerivation.ts`），常量 `ACCOUNT_SECRET_KEY_LENGTH = 128` 不变。
- **不改成助记词**：不使用 12 / 24 词助记词，不引入新的密钥格式与校验规则。
- **展示方式沿用原 Emergency Kit**：首次创建时只展示一次，界面与导出文件均按原 Emergency Kit 的版式：
  - 标题 `BearPassword Emergency Kit`、保管提示、分隔线；
  - 创建时间、密钥指纹（原算法：对密钥原文做 SHA-256 摘要后 Base64 编码）；
  - 密钥本身为**单行完整 128 位字符串**，不分段、不掩码、不截断；
  - 文件末尾保留“请勿与他人分享”提示；导出文件为 `.txt`，文件名保留 `BearPassword-Emergency-Kit` 前缀。
- **唯一改动是去账号化**：新版无账号、无用户名、无注册邮箱，因此 Emergency Kit 内容与文件名中**去掉用户名段与邮箱 / 账号行**，其余版式、长度、指纹算法不变。
- **已配置后不再明文显示**：设置中恢复密钥已配置时只显示“已配置”与指纹，不显示密钥原文；再次查看完整密钥必须先通过手机令牌验证；复制后按现有剪贴板清空策略处理。

## 5. 数据管理与兼容定稿

### 5.1 加密备份（本版自身备份，保留）

- 加密备份导出：单个加密文件，不含明文；可设独立备份口令或复用主密码派生；导出时明示“文件仍需妥善保管，软件不会替你上传”。
- 加密备份导入：校验完整性与口令；默认策略为“导入前强制备份当前库，导入整体替换当前库”，不做静默合并（无同步后，合并的冲突语义无从定义，宁可保守）。
- 导入只认本版自身导出的加密备份文件。

### 5.2 数据目录与删除

- 数据目录可配置：沿用原离线保险库 `dataDir` 概念，默认系统应用数据目录；换目录需校验旧数据可读（指本版格式的数据，不是旧版数据）。
- 删除本地库：主密码 + 手机令牌双重确认，删除前强制导出备份，不可逆并明示。

### 5.3 兼容性：不兼容旧用户（v3 锁定，开发不实现）

- **不面向旧用户**：本地版按全新产品交付，首次使用即全新创建保险库。
- **不做旧版迁移**：不实现旧版数据读取、版本转换、旧库自动迁移引导；不实现“旧云端账号自动同步、旧离线库首次启动转换、补绑令牌后沿用旧库”这类流程。
- **不复用旧版密钥材料**：旧版 Emergency Kit / 账户密钥、旧版导出的任何文件，均不直接当作新版恢复密钥或新版备份导入；新版恢复密钥一律在首次创建时重新生成（格式见第 4 节，材料是新生成的，不是旧的）。
- **不承诺旧格式导入**：旧版加密备份、旧版 CSV 与其他旧版导出格式，均不在新版导入承诺范围内；发布文档与引导文案中不得出现“旧数据会自动出现 / 可一键迁移”的表述。
- **后果明示**：旧用户如需使用本地版，需接受从零开始新建保险库；这一点须在发布文档中写清，避免用户误以为换新版后旧数据还在。

## 7. 浏览器扩展定稿（保留本机桥接）

- **锁定保留**：扩展只与本机桌面端通信，不连服务器，不走任何云端接口。
- 桥接只在“已解锁”态响应；桌面端锁定、未通过手机令牌验证或退出时，扩展返回“桌面端未解锁”，不缓存条目明文；桌面端锁定后桥接会话失效，解锁后恢复。
- 扩展相关文件保留：`src/extensionBridge/`、`electron/main/extensionBridgeServer.ts`、`electron/preload/index.ts` 中的桥接暴露与 `bear-password-extension/`；根构建保留扩展打包步骤。

## 8. 生物识别定稿（保留快捷解锁）

- 保留 Touch ID / Windows Hello，定位为**本机快捷解锁**，不是令牌的替代品。
- 应用启动后的首次解锁仍需主密码 + 手机令牌；生物识别仅在“已通过令牌验证的会话内”作为快捷解锁使用，不得绕过令牌直接进入保险库。
- 相关逻辑：`src/stores/biometricUnlock.ts`、`electron/main/biometricAuth.ts` 的触发条件按上述规则收紧；未通过令牌验证时生物识别不能直接进保险库。

## 9. 安全与验收（定稿版，全部为必过项）

1. 断网全流程可用：创建、绑定、解锁、增删改查、条目内 TOTP、锁定、导出导入。
2. 无账号残留：全新安装找不到注册 / 登录 / 邮箱 / 服务器地址入口；代码中搜不到对 `/auth/login`、`/auth/register`、`/api` 服务端的调用（本地桥接除外）。
3. 无已删模块残留：仓库与构建脚本中搜不到 `bear-password-web`、`bear-password-server`、`bear-password-index` 的构建引用；打包产物中无网页端、服务端、官网产物。
4. 令牌：正确码解锁；过期码、错码、重放码拒绝；连续失败触发锁定；换绑后旧码失效；6 位动态码校验与 ±1 步容差符合第 3.3 节。
5. 丢失：仅主密码 + 恢复密钥可重绑；单点“忘记令牌”不能绕过；恢复密钥为 128 位格式，展示一次，配置后只显示指纹。
6. 加密：数据文件与备份文件无明文密码与 TOTP 密钥；锁定后内存敏感数据清除，扩展不可读；令牌密钥与条目内 TOTP 密钥、恢复密钥存储隔离。
7. 生物识别与扩展：首次解锁无令牌不能靠生物识别进入；锁定后扩展不可读。
8. 构建：桌面端 `npm run typecheck`、`npm run build`、macOS / Windows 打包通过；Web、Server、Index 已从构建脚本移除。
9. 回归：条目 CRUD、收藏、最近访问、搜索、条目内 TOTP、自动锁定、剪贴板清空、主题语言切换无退化。
10. **无迁移验收项**：因第 5.3 节不兼容旧用户，验收清单中不再设旧库迁移、旧云端导入用例；发布文档须写清“全新创建、无旧数据迁移”。

## 10. 待确认项：无

v2 的全部待确认项已在本版关闭：扩展保留、令牌默认 6 位、关闭令牌验证入口不开放、恢复密钥沿用原账户密钥格式、生物识别保留为快捷解锁、官网模块删除、旧用户不兼容。开发可按本版直接开工，无需再等拍板。
