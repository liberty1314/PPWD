# TASK-UIR-09 发布准备与回滚

## 发布门禁

当前发布结论：**HOLD / 不发布**。桌面和扩展真人验收、Edge、Windows x64 installer 验证尚缺。此文档中的步骤用于门禁解除后的分批发布。

发布前逐项确认：

- [ ] Desktop 与 Extension 的类型检查、生产构建、相关测试和生产依赖审计通过；测试报告记录版本与产物校验值。
- [ ] P0/P1 缺陷为零，或由项目维护者记录明确接受意见和跟进人。
- [ ] 桌面认证、恢复、保险库敏感操作和备份恢复真人验收签认。
- [ ] Chrome 与 Edge 最终 ZIP 安装/升级、popup、网页匹配、自动填充、TOTP、快速保存、wake 和浏览器重启旅程验收。
- [ ] macOS arm64 DMG 安装/启动/升级验证；Windows x64 installer 在 Windows 上安装、启动、快捷方式和卸载验证。
- [ ] 扩展升级不会清除既有浏览器 storage；桌面升级不会改变用户保险库文件、偏好键或加密数据。
- [ ] 最终安装包、扩展 ZIP、发布说明和回滚责任人已确认；对外发布所需签名/公证按发布策略完成。

## 发布步骤

1. 固定发布 commit 和版本号；从干净工作区按仓库正式构建命令生成 desktop 与 extension 产物，记录 SHA-256、版本、架构和构建日志。
2. 在干净测试账户/浏览器 profile 安装产物，按 [人工验收记录](task-ui-refactor-09-manual-acceptance.md) 执行核心旅程。不得使用或清理真实用户 profile 做验证。
3. 先向维护者/小范围测试用户发布 macOS 和扩展候选包；Windows 候选包完成平台验证后纳入同一发布批次。
4. 观察启动、解锁、扩展 bridge、填充失败率及用户反馈；确认无 P0/P1 后再扩大分发。
5. 保存前一稳定版安装包、扩展商店/分发所需回退版本及发布记录。记录升级前后版本和存储兼容性结果。

## 回滚步骤

### Desktop

1. 暂停分发新版本并通知用户停止重复安装/卸载操作。
2. 分发前一稳定版本安装包，按平台正常覆盖安装或卸载后安装；禁止删除用户数据目录、保险库文件或配置文件。
3. 若新版本已迁移偏好，只回退代码/应用版本，不手工覆盖或删除偏好键；确认旧版本能忽略新增偏好字段。
4. 用专用测试保险库验证旧版可启动、解锁和读取数据；真实用户数据恢复只使用受支持的备份流程。

### Browser extension

1. 停止新 ZIP/商店版本分发，并恢复前一稳定扩展包或发布版本。
2. 优先覆盖/降级安装，避免卸载扩展；卸载可能删除浏览器 storage。需要卸载时先遵循产品支持的数据导出/备份流程并明确提示用户。
3. 验证旧版 popup、desktop bridge 和网页自动填充恢复；确认现有 storage key 与 session 行为可读。

### 回滚后检查

- [ ] 记录触发回滚的缺陷、受影响版本/平台、负责人和修复版本。
- [ ] 用专用测试数据验证本地保险库仍可解锁，扩展数据仍保留；不得通过重置用户数据掩盖问题。
- [ ] 重新发布前补充回归用例和人工验收证据，更新本 TASK-UIR-09 报告及计划门禁。
