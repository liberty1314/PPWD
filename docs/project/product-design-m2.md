# 手机令牌门禁用户流程

## 目的与范围

落实需求 v3 第 3、4、8 节已锁定的本地创建、令牌绑定、解锁、换绑、丢失恢复和生物识别快捷解锁路径。沿用桌面端 Element Plus 视觉与交互组件，不改变条目管理体验。

## 关键流程

1. 首次启动进入创建页，输入并确认主密码；系统生成 128 字符 Base64URL 恢复密钥。
2. 创建页单独展示恢复密钥、指纹和保管提示；用户确认已保存后，本机安全存储写入保险库校验配置与恢复密钥。创建失败保留当前步骤和输入，已有数据目录要求用户选择空目录，不执行合并或迁移。
3. 进入绑定页后展示 TOTP 二维码及一次性手动密钥；用户输入主密码和 6 位码。验证成功后令牌密钥才写入系统安全存储并进入主界面。
4. 未启用快捷解锁时，冷启动及锁定后输入主密码与手机动态码；启用生物识别偏好后，优先生物识别，并可仅输入手机动态码。失败提示统一为“验证失败”，限流由主进程强制执行。
5. 手机丢失时从解锁页进入恢复页，验证主密码和完整恢复密钥；成功后旧令牌立刻作废，再进入绑定页。不能仅用其中一个材料进入主界面。
6. 设置中换绑需旧动态码与主密码；旧绑定作废后重用绑定页。恢复密钥查看需再次通过手机令牌验证，关闭后清除页面中的密钥明文。
7. 启用生物识别偏好后，应用冷启动及锁定时均优先生物识别；也可仅输入 TOTP。关闭偏好后恢复主密码 + TOTP。

## 页面与状态

| 页面 | 入口 | 主要状态 | 退出条件 |
| --- | --- | --- | --- |
| 创建保险库 | 无本地元数据 | 密码输入、恢复密钥一次性展示、安全存储错误、已有数据目录 | 保存恢复材料后进入绑定 |
| 绑定手机令牌 | 保险库已创建但未绑定 | 二维码、手动密钥、错误码、锁定、存储不可用 | 动态码与主密码通过 |
| 解锁 | 已绑定且 VUK 不在内存 | 生物识别优先、TOTP 单独解锁、主密码与 TOTP、统一失败、锁定 | 当前偏好要求的认证通过 |
| 恢复 | 解锁页主动进入 | 主密码与恢复密钥输入、错误、锁定 | 双因素通过后令牌作废并转绑定 |
| 设置安全 | 保险库已解锁 | 换绑验证、恢复密钥再次验证、密钥短暂展示 | 操作成功或关闭清除敏感状态 |

## UI 变更清单

- 路由：`/setup`、`/bind`、`/unlock`、`/recover`；主应用路由要求保险库已解锁。
- 组件：首次创建/恢复材料展示、令牌扫码绑定、日常解锁/恢复表单、安全设置面板。
- 用户旅程：首次创建、退出后续作、错误/锁定恢复、换绑、手机丢失恢复、冷启动与自动锁定。
- 关键状态：默认、加载、已配置、错误、存储不可用、重复提交、被路由门禁拒绝。
- 目标环境：macOS 与 Windows 桌面包；真人检查主窗口常用尺寸及窄窗口、键盘操作和焦点顺序。

## 可访问性与安全交互

- 表单标签明确标注主密码、6 位动态码与恢复密钥；动态码只接受数字。启用生物识别偏好后解锁页隐藏主密码输入，提供生物识别主操作和动态码解锁备选。
- 密钥值使用只读、可复制区域，不写剪贴板除非用户主动复制；离开页面清理组件状态。
- 错误文案不区分主密码与 TOTP 错误，不在日志或界面输出密钥。
- 令牌不可用、安全存储不可用和锁定时显示明确的恢复路径，不暴露绕过入口。
